# VSCode Switcher

Нативное macOS-приложение (агент в строке меню, без иконки в доке). Курсор к левому краю
экрана — выезжает панель со списком открытых окон VSCode: цвет проекта, тема активного чата
Claude, состояние агента, число фоновых сабагентов, занятый контекст и модель. Ниже — список
неоткрытых проектов из папки проектов: клик открывает новое окно.

Полное ТЗ и разбор источников данных — в [`docs/SPEC.md`](docs/SPEC.md).

## Как пользоваться

- **Открыть панель**: подвести курсор к левому краю экрана и задержать ~150 мс. Работает не
  вся грань, а только её средняя часть — ровно там, где появится сама панель; сверху и снизу
  остаются свободные полосы, вдоль которых можно вести мышь, ничего не вызывая.
  Панель появляется на том мониторе, где сейчас курсор.
- **Клик по строке**: открытое окно — фокус на него (macOS сам переключит Space);
  неоткрытый проект — открывается новое окно VSCode на его `.code-workspace` (или на папке,
  если воркспейс-файла нет).
  **Панель при этом остаётся открытой** — можно перебирать окна подряд.
- **Поиск**: клик в поле сверху; фильтрует по имени проекта и теме чата. Пока в поле не
  кликнули, панель не забирает клавиатуру у редактора.
- **Закрыть панель**: увести курсор за её пределы (в любую сторону) или кликнуть мимо.
  Клавиатурного управления нет — панель мышиная.
- Строка фронтового окна подсвечена; наведение подсвечивает строку под курсором.
- Подсказка (tooltip) строки показывает описания активных фоновых сабагентов.

Состояния агента: оранжевый (ждёт разрешения, пульсирует), зелёный (ответил, ждёт реакции),
синий (работает, пульсирует), серый (простаивает). Цифра рядом — сколько чатов окна в этом
состоянии.

Если процент контекста не показан, а вместо него голое число вроде `180k` — значит размер
окна контекста достоверно неизвестен. Это честнее заведомо неверного процента.

## Сборка и установка

Нужен Xcode Command Line Tools (Swift 5.9+) и macOS 14+.

```sh
make app        # собрать macos/VSCodeSwitcher.app
make install    # собрать, положить в /Applications и запустить
make run        # собрать и запустить из репозитория, без установки
make test       # swift test
make dump       # напечатать собранную модель в консоль (диагностика)
make clean
```

Автозапуск: «Системные настройки → Основные → Объекты входа» → добавить
`/Applications/VSCodeSwitcher.app`.

## Доступ к Accessibility

Без него не видно окон VSCode — панель покажет только список проектов (состояния Claude-агентов
при этом видны, они читаются с диска и разрешения не требуют).

1. Запустить приложение. При первом старте оно один раз покажет системный промпт.
2. «Системные настройки → Конфиденциальность и безопасность → Универсальный доступ» →
   включить `VSCodeSwitcher`.
3. Перезапустить приложение.

То же самое можно сделать из меню в строке меню: **Проверить разрешения** — или кликом по
оранжевой плашке в самой панели.

> **Важно про пересборку.** `.app` подписывается ad-hoc (`codesign --sign -`), а macOS
> привязывает выданное разрешение к паре «bundle id + хеш подписи». Поэтому **после каждой
> пересборки доступ слетает**: галочка в списке остаётся стоять, но `AXIsProcessTrusted()`
> возвращает `false`, а системный промпт больше не показывается — запись-то уже есть.
> Лечится вручную: в списке «Универсальный доступ» снять галочку с `VSCodeSwitcher` и
> поставить заново (или удалить строку кнопкой «−» и заново запустить приложение).

## Хуки Claude Code

Состояние агента (`working` / `waiting` / `permission`) приходит из хуков Claude Code, а модель
и занятый контекст — из `statusLine`. Без них панель работает, но состояние определяется по
транскрипту и отстаёт на десятки секунд.

```sh
make hooks                        # = scripts/install-hooks.sh
scripts/install-hooks.sh --debug  # плюс дамп сырых payload'ов в ~/.claude/window-status/_debug.jsonl
scripts/install-hooks.sh --uninstall
```

Или пункт меню **Установить хуки** — он запускает тот же скрипт (в собранном `.app` лежит его
копия в `Contents/Resources/scripts/`).

Скрипт идемпотентный: делает бэкап `~/.claude/settings.json`, удаляет только свои записи и
добавляет их заново, чужие хуки не трогает. Нужен `jq`.

## Конфиг

`~/.config/vscode-switcher/config.json`, необязателен — у всех полей есть значения по
умолчанию. Пункт меню **Открыть конфиг** создаёт файл с текущими значениями и открывает его.

```json
{
  "projectRoots": ["~/Data/Projects"],
  "scanDepth": 2,
  "dwellMilliseconds": 150,
  "panelWidth": 380,
  "panelHeightFraction": 0.7,
  "subagentActiveSeconds": 90,
  "transcriptTailBytes": 524288,
  "editorBundleID": "com.microsoft.VSCode"
}
```

| Поле | Смысл |
|---|---|
| `projectRoots` | каталоги, где искать проекты (папка считается проектом, если в ней есть `*.code-workspace` или `.git`) |
| `scanDepth` | глубина вложенности от корня; `2` находит и `Projects/foo`, и `Projects/wirenboard/bar` |
| `dwellMilliseconds` | сколько держать курсор у края, чтобы панель выехала |
| `panelWidth` | ширина панели в точках |
| `panelHeightFraction` | высота панели как доля рабочей области экрана; та же доля задаёт высоту зоны срабатывания у левого края |
| `subagentActiveSeconds` | сабагент считается активным, пока его транскрипт трогали не дольше стольких секунд назад |
| `transcriptTailBytes` | сколько байт читать с конца транскрипта (они бывают по 24 МБ) |
| `editorBundleID` | bundle id редактора, чьи окна перечисляются |

Изменения подхватываются при перезапуске приложения.

## Диагностика

```sh
./macos/.build/release/VSCodeSwitcher --dump          # собранная модель текстом
./macos/.build/release/VSCodeSwitcher --dump --json   # то же в JSON
./macos/.build/release/VSCodeSwitcher --no-windows    # запуск без окон редактора:
                                                      # так панель выглядит без Accessibility
```

## Известные ограничения

- **Два окна на один проект.** Сессии Claude распределяются между ними эвристикой: активный
  чат окна определяется сравнением префикса заголовка окна с `ai-title` сессий, остальные
  сессии проекта приписываются переднему окну.
- **Заголовок окна меняется сам по себе** (VSCode пишет туда активный файл и тему чата), а
  z-order сдвигается от каждого клика. Поэтому перед фокусом окно ищется заново по
  `pid` + `rootName`. Если два окна одного проекта открыты одновременно, попасть можно не в то.
- **Пересборка сбрасывает Accessibility** — см. выше.
- Панель не забирает фокус при показе, поэтому поле поиска не получает курсор автоматически:
  в него нужно кликнуть.
- Приложение не подписано Developer ID и не нотаризовано: при первом запуске скачанного
  бандла Gatekeeper будет ругаться. Локальная сборка через `make app` этой проблемы не имеет.
